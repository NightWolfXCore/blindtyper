# Архитектура BlindTyper

Статус: проект архитектуры для команды из трёх человек. Контракты v1 становятся общей точкой интеграции; их изменения согласуются до изменения реализации.

## 1. Основное решение

Одно PHP-приложение, один домен, одна база MySQL. PHP отдаёт статические страницы и JSON API `/api/v1`. JavaScript выполняет интерактивную тренировку в браузере. Авторизация — через серверные сессии и cookie. Перезагрузка страницы завершает текущий интерфейс тренировки; восстановление незавершённой тренировки в v1 не предусмотрено. Сохранённые результаты доступны после входа с любого устройства.

Стек:

| Область | Решение |
| --- | --- |
| Сервер | PHP 8.2+, расширения pdo_mysql, mbstring, intl; Composer для автозагрузки PSR-4 |
| Данные | MySQL 8.0+, InnoDB, utf8mb4, UTC |
| Интерфейс | HTML, CSS, Bootstrap 5, JavaScript ES modules |
| Графики | Chart.js |
| Локальный запуск | PHP CLI web server и локальный MySQL |
| Публикация | Nginx/Apache + PHP-FPM + MySQL, HTTPS |
| Проверки | PHPUnit для бэкенда; браузерные сценарии для интерфейса; SQL-проверки миграций |

Node.js не нужен для работы приложения. Для UTF-8 используется mbstring, для нормализации NFC — intl. Bootstrap и Chart.js размещаются локально с зафиксированными версиями, чтобы показ прототипа не зависел от CDN. Продукционный document root — только `public/`.

## 2. Зоны ответственности

| Участник | Отвечает за | Основные пути | Передаёт остальным |
| --- | --- | --- | --- |
| Бэкенд — пользователь и Codex | Маршруты API, аккаунты, сессии, CSRF, проверка тренировок, опыт, уровни, достижения, статистика и рейтинг | `src/`, `config/`, `public/index.php`, `tests/backend/`, `composer.json`, `composer.lock` | Реализацию API и безопасную запись данных |
| Фронтенд | Экраны, адаптивность, ввод, клавиатура с пальцами, предварительные показатели, анимации, графики, API-клиент | `public/pages/`, `public/assets/`, `tests/frontend/` | Интерфейс и демонстрационные ответы API |
| База данных | SQL-схема, миграции, индексы, ограничения, словари, упражнения, справочник достижений, проверка запросов | `database/`, `tests/database/` | Воспроизводимую БД, тестовые данные, описание миграций |

Бэкенд владеет правилами начисления и SQL-запросами приложения. Разработчик БД проектирует их поддержку, проверяет индексы и предлагает оптимизацию. Карта RU/EN-клавиш, цвета пальцев и подсказки постановки рук принадлежат фронтенду и хранятся в его статических данных. Фронтенд не обращается к MySQL. Разработчик БД не дублирует игровую логику в триггерах.

Общие документы `docs/` изменяются с уведомлением остальных участников. Ветки: `backend/*`, `frontend/*`, `database/*`; интеграция через PR в `main`. Миграции создаёт участник БД после согласования с бэкендом; уже применённые миграции не редактируются.

## 3. Структура проекта

```text
blindtyper/
├── public/
│   ├── index.php                 # единая точка входа PHP, API и маршруты страниц
│   ├── pages/                    # HTML-шаблоны интерфейса
│   └── assets/
│       ├── css/
│       ├── js/
│       │   ├── api.js            # fetch, cookie, CSRF, обработка ошибок
│       │   ├── trainer/          # ввод, таймер, клавиатура, эффекты
│       │   └── pages/            # аккаунт, статистика, рейтинг
│       └── vendor/              # Bootstrap и Chart.js
├── src/
│   ├── Http/                    # маршрутизатор, middleware, JSON-ответы
│   ├── Controller/              # чтение запроса и вызов сервисов
│   ├── Service/                 # Auth, Training, Scoring, Progress, Statistics
│   ├── Repository/              # PDO-запросы, без HTTP и UI
│   └── Domain/                  # формулы, уровни и правила достижений
├── config/                      # загрузка настроек, без паролей в Git
├── database/
│   ├── migrations/              # последовательные SQL-изменения
│   ├── seeds/                   # упражнения и справочники
│   └── README.md                # применение и проверка миграций
├── tests/{backend,frontend,database}/
└── docs/
```

Каталоги перечислены как целевая структура: пустые каркасы не обязательны. Маршруты страниц: `/` — тренажёр, `/login`, `/register`, `/profile`, `/leaderboard`. Разработчик фронтенда создаёт шаблоны; бэкенд подключает их по маршрутам. Пользовательские данные загружаются через API.

## 4. Сценарий тренировки

1. Пользователь входит и запрашивает настройки через `GET /catalog`.
2. Выбирает режим, язык и сложность. Сервер проверяет доступность и создаёт тренировку через `POST /sessions`.
3. Сервер сохраняет неизменяемый текст и версию правил; возвращает текст и параметры подсчёта.
4. Пользователь нажимает «Начать»: `POST /sessions/{id}/start`. После ответа фронтенд запускает монотонный таймер `performance.now()` и принимает ввод.
5. JavaScript немедленно подсвечивает символы, считает предварительные показатели и хранит последовательность вводов в памяти. Сетевой запрос на каждую клавишу не нужен.
6. После окончания текста фронтенд отправляет события в `POST /sessions/{id}/finish`. Сервер повторяет обработку событий, вычисляет показатели и сохраняет результат одной транзакцией.
7. Фронтенд показывает окончательные серверные значения, новый уровень и достижения. При сетевой ошибке повторяет тот же запрос; сервер не начисляет опыт повторно.

В v1 все тренировки завершаются по окончании текста, таймер показывает время выполнения. Гость может просматривать страницы и описание, но сохраняемые тренировки требуют входа. Выход со страницы оставляет тренировку незавершённой и не начисляет опыт.

## 5. Единые правила v1

### Ввод и скорость

- Режим строгий: ошибка фиксируется, позиция в тексте не продвигается; нужно ввести ожидаемый символ. Пропуск символов не разрешён. Backspace не отменяет предыдущие события и не стирает ошибки.
- Считаем Unicode code points (`Array.from` в JS; UTF-8-совместимая обработка в PHP). Учебные тексты нормализованы в NFC, окончания строк — LF. Emoji и комбинируемые последовательности не входят в упражнения v1.
- Регистр, пробелы, цифры, знаки и перенос строки значимы. Отступы кода — пробелы; табуляции в исходных текстах запрещены. Enter вводит `\n`, Tab не вводит символ и сохраняет стандартную навигацию по странице.
- Событие — один напечатанный символ. Служебные клавиши и отдельное нажатие Shift/Ctrl/Alt не считаются. Используется поле ввода и события `beforeinput`/`input` с учётом composition; вставка, автозаполнение и многоcимвольная вставка запрещены. Для v1 поддерживаются аппаратная клавиатура и RU/EN без IME; мобильный ввод требует отдельной проверки.
- Неверная раскладка даёт ошибку; приложение показывает ожидаемую RU/EN-раскладку, но не переключает раскладку ОС.
- `correct` — количество совпавших вводов; `errors` — несовпавших; `attempts = correct + errors`.
- `CPM = correct × 60000 / duration_ms`; `WPM = CPM / 5`, включая русский язык. Это условные слова по пять символов.
- `accuracy = 100 × correct / attempts`. При отсутствии попыток интерфейс показывает 0; такая тренировка не сохраняется как результат.
- Значения рассчитываются без промежуточного округления; API округляет скорость и точность до двух знаков.

### Опыт и уровни

- Каждый правильный символ даёт базово 1 XP. Ошибка сбрасывает серию.
- Множитель серии: 1–19 → x1, 20–49 → x2, 50–99 → x3, от 100 → x5. Порог применяется уже к символу, который его достиг.
- `level = 1 + floor(sqrt(total_xp / 100))`; следующий уровень требует `100 × level²` суммарного XP.
- Слова доступны с уровня 1, предложения — 2, символы — 3, код — 4. Сложности `easy`, `medium`, `hard` доступны внутри открытого режима.
- Для демонстрации всех режимов предусмотрен явно обозначенный демонстрационный аккаунт с начальным уровнем 4. Обычный аккаунт начинает с 0 XP.
- Временный бонус: удвоение XP на 10 секунд. Сервер заранее генерирует расписание, сохраняет и возвращает его с тренировкой. Бонус применяется по времени события, на интервале `[starts_at_ms, ends_at_ms)`; множится на комбо. Скорость печати бонусами не изменяется.
- Достижения v1: первая завершённая тренировка; CPM ≥ 200; 1000 правильных вводов подряд в одной тренировке. Последнее требует длинного упражнения: каталог должен содержать вариант на 1000–1500 символов. Достижения выдаются один раз, дополнительный XP за них в v1 не начисляется.

Версия `rules_version = 1` сохраняется в каждой тренировке. Изменение формул требует новой версии и явного решения о совместимости старых результатов.

## 6. Безопасность и проверка результата

PHP проверяет владельца тренировки, состояние, доступность режима, последовательность событий и их временные отметки. Текст, множители, XP, уровень и достижения берутся из серверных данных, а не из присланных итогов.

Длительность результата берётся из последнего события относительно старта. Время с момента серверного старта служит проверкой: длительность клиента не должна превышать серверное прошедшее время более чем на 2 секунды. Последовательность событий должна быть непрерывной, время — неубывающим. Для рейтинга: не менее 100 правильных символов и 10 секунд, CPM не более 1500. Более быстрый результат сохраняется с `ranked=false`; XP ограничивается правилами упражнения и лимитами частоты.

Такая проверка отсекает простую подмену готовых чисел, но не доказывает, что печатал человек: клиентские события можно подделать. Полноценный античит выходит за рамки прототипа.

Пароли: `password_hash`/`password_verify`. Сессии: cookie `HttpOnly`, `SameSite=Lax`, `Secure` при HTTPS, смена ID при входе. CSRF обязателен для изменяющих запросов, в том числе входа и регистрации. SQL — только подготовленные запросы PDO. Вывод текста — через `textContent` либо экранирование HTML. Пароли БД и секреты не коммитятся. Нужны лимиты попыток входа и создания тренировок; тело finish ограничено 2 МБ и 20000 событий.

## 7. Что участники могут делать параллельно

**Бэкенд:** реализовать маршрутизатор, формат ответа, сессии и CSRF; затем AuthService, расчёт результата и транзакцию завершения. Для модульных тестов использовать репозитории в памяти до готовности MySQL.

**Фронтенд:** реализовать экраны и `api.js` по контракту; временно возвращать из того же интерфейса API-клиента фиксированные демонстрационные данные. Затем заменить реализацию запросами fetch без изменения экранов. Расчёт в браузере предварительный, после finish показывать серверный результат.

**БД:** подготовить миграции и seed по контракту данных; дать бэкенду рабочую базу с упражнениями RU/EN, кодом и тестовым аккаунтом. Проверить индексы для рейтинга и статистики.

Первый общий вертикальный сценарий: регистрация → слова → завершение → сохранённый результат в профиле. После него подключаются остальные режимы, достижения, аналитика и эффекты.

## 8. Проверки готовности

- Бэкенд: формулы CPM/WPM, ошибки и комбо на границах 20/50/100, бонус на границах времени, уровни; чужая тренировка; CSRF; повторный finish; откат транзакции при ошибке.
- Фронтенд: RU/EN, Shift, пробел, Enter, потеря фокуса, запрет вставки, отсутствие задержек, корректное отображение ошибки сервера и повтор сохранения. Таймер при потере фокуса продолжает идти.
- БД: развёртывание с нуля, повторный seed без дублей, уникальные email и достижения, внешние ключи, UTC, совместимость регистра email, индексы и EXPLAIN рейтингов.
- Интеграция: вход → все четыре режима → сохранение → повторный вход с другого браузера → тот же прогресс; дневной и недельный рейтинги.

Вход через email/пароль покрывает вариант авторизации из ТЗ. Социальный вход можно добавить позже. Примеры достижений в ТЗ не требуют буквального порога 300 WPM; продуктовые пороги зафиксированы выше. Бонус «+50% к скорости» заменён бонусом XP, чтобы статистика отражала фактическую скорость.
