# Установка начальной базы данных

Нужны MySQL 8.0+, PHP 8.2+ с `pdo_mysql`, `mbstring` и `intl`, установленные зависимости Composer и **пустая** база MySQL. Подключение задаётся переменными `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`; PHP не читает `.env` без Docker Compose. SQL-миграцию нужно выполнять под пользователем с правами на создание и изменение таблиц.

Из корня проекта в Docker:

```sh
docker compose run --rm app php bin/install-database.php
```

Без Docker, после настройки переменных окружения:

```sh
php bin/install-database.php
```

Установщик применяет `migrations/0001_initial.sql`, записывает `0001_initial` в `schema_migrations`, затем в одной транзакции применяет `seeds/0001_initial_data.sql` и создаёт дополнительные упражнения длиной 120, 240 и 1200 символов для всех сочетаний параметров API. После успешной записи seed получает метку `seed_0001_complete_catalog`. Исходные 30 текстов остаются в базе; для них пересчитывается фактическая длина. Исходные тексты режима `words`, содержащие слова длиннее 10 букв, становятся неактивными, но сгенерированные из них упражнения остаются доступными.

Повторный запуск по меткам ничего не добавляет. Установщик отказывается работать с уже заполненной базой без метки миграции или с заполненным каталогом без метки seed: фиксированные ID исходных упражнений могли бы столкнуться с чужими данными. Базу, ранее созданную через `bin/dev-database.php`, он не преобразует. Для неё нужна отдельная миграция с сохранением аккаунтов, тренировок и ссылок на упражнения; новый проект можно поднять в отдельной пустой базе. Не редактируйте уже применённый SQL-файл миграции — новые изменения оформляйте следующей миграцией.

Исходный seed даёт 30 коротких упражнений. Дополнительные упражнения пока строятся повторением и обрезкой этих образцов, поэтому длинные тексты функциональны, но однообразны; перед публикацией их стоит заменить авторскими. Установка новой базы и SQL ещё не проверены в этом изменении на работающем MySQL.
